## Checkpoint

Checkpoint 使用独立 Git 存储记录 Workspace 状态，并与消息关联。它服务于 Agent 修改的恢复，不替代用户自己的 Git 提交。

## Rewind

Rewind 从指定消息恢复对话和文件状态。执行前必须检查:

- 当前是否有活动 run。
- 工作树是否存在未保存修改。
- 恢复点是否属于当前 Session 和 Workspace。
- 操作是否需要用户审批。

Rewind 不是普通消息删除。它会改变文件状态，必须显示预览和影响范围。

## Worktree

Worktree 为并行任务提供文件系统隔离。每个 Agent 或任务可以绑定独立工作树，避免在同一目录并发改写文件。

## 选择方式

- 需要回到某条消息对应状态 -> Checkpoint 和 Rewind。
- 需要同时执行多个修改任务 -> Worktree。
- 只需要从历史继续讨论，不改变文件 -> Session fork。

任何恢复操作都不能静默丢弃用户未提交修改。
