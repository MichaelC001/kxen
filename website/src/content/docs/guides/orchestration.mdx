## Goal

Goal 用于跨多轮持续执行的任务。创建时必须提供 objective 和可观察的 completion criteria。

生命周期:

```text
create -> activate -> execute -> validate -> complete
                                      -> blocked
```

Goal 可以限制 token、turn 和 wall clock。只有完成条件逐条验证通过后才能进入 complete。同一阻塞原因连续出现 3 轮后才能进入 blocked。

## Dynamic Workflow

Workflow 由模型生成 JavaScript，并在 QuickJS 沙箱中执行。常用原语包括:

- `agent()`
- `pipeline()`
- `phase()`
- `constraints()`

Workflow 适合并行、循环、分支和中间结果较多的任务。沙箱限制内存、栈、Agent 调用次数和总运行时间。用户取消会中断运行。

## Subagent

Subagent 具有独立上下文，并继承角色权限。研究和规划角色默认只读，execution 角色才获得写入和命令能力。

## Agent Teams

Team 由 lead 和多个 member 组成。成员拥有独立 inbox、任务和转录，可以绑定不同角色、模型和 Worktree。

共享任务支持:

- pending、in_progress 和 completed 状态。
- assignee。
- depends_on。
- 自动解锁依赖。
- member 间消息。

## 选择方式

- 单一目标、少量工具调用 -> 普通 Session。
- 需要完成条件和跨轮持续 -> Goal。
- 可编码的并行和分支 -> Workflow。
- 独立上下文的短任务 -> Subagent。
- 长时间协作和共享任务 -> Agent Teams。
