Rewind 把 Session 和 Workspace 回退到某条消息对应的恢复点。它不是普通消息删除，因为操作会改变真实文件。

## 发起

在 Session 时间线的可恢复消息上选择 Rewind。执行前，kxen 检查:

- 当前是否存在活动 run。
- Checkpoint 是否属于当前 Session 和 Workspace。
- 工作树是否存在未保存修改。
- 恢复范围是否需要用户确认。

## 影响

Rewind 会删除目标消息之后的 Session 历史，并恢复 Checkpoint 记录的文件状态。后续工具结果、Approval 记录和 Assistant 输出不再属于当前时间线。

## 保护用户修改

当文件在 Checkpoint 之外发生变化时，Rewind 不能静默丢弃这些修改。界面需要展示影响范围，并在无法安全恢复时停止操作。

## 与 Fork 的区别

Fork 从历史消息前或后创建有谱系的新 Session，保留原 Session 和原回复。编辑重发与重新生成也使用 Fork 语义，因此不会覆盖既有时间线。分支拥有独立对话、队列、运行和草稿，但仍读取同一 Workspace 的当前文件状态。

只想从旧对话继续探索时使用 Fork。需要隔离两个方向的文件修改时使用独立 Worktree。明确需要撤回当前 Session 的 Agent 文件修改时才使用 Rewind。
